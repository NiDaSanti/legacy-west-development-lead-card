# Close CRM + Gmail Follow-Up Integration (Planning Doc)

> **Status: Planned / Not yet implemented.** This document tracks the design and rollout plan for connecting the lead form to Close CRM (structured custom fields) and Gmail (automatic follow-up drafts), including fire-recovery branching logic. Nothing described below has been built yet — see [Status Tracker](#status-tracker) for what already exists today.

---

## Goal

When a lead is submitted through the form:
1. Create a lead in Close CRM with data mapped to **real Close custom fields** (not just plain-text notes, as done today).
2. Automatically generate a **Gmail draft** follow-up email addressed to the lead.
3. Use a **different email template** if the lead was affected by the Altadena fires, versus a standard follow-up.
4. Log an activity/note back on the Close lead confirming a draft was created, so the team has visibility without leaving Close.

## Architecture Note

This integration will extend the **existing** Express API on Render (`server.js`) — it does **not** require Netlify Forms or a separate service. The form already POSTs directly to `POST /api/create-lead`; that same endpoint (or a set of related endpoints) will be extended to also create the Gmail draft and structured Close fields, keeping the existing split architecture (Netlify frontend → Render backend → third-party APIs) intact.

See the main [`README.md`](../README.md) for the current architecture diagram and deployment details.

## Open Decisions (Need Answers Before Implementation)

These need to be resolved before any code is written:

### 1. Gmail authentication method
- **Option A — Google Workspace service account with domain-wide delegation** (recommended if `legacywestdevelopment.com` is a Google Workspace domain, which appears to be the case based on team email addresses already in use with Close).
- **Option B — OAuth2 with a stored refresh token** for a single personal/shared Gmail account.

> Decision impacts: setup steps in Google Cloud Console, what credentials get stored in Render's environment variables, and whose Google account "owns" the integration long-term.

### 2. Whose inbox receives the draft?
- A single shared/team inbox (e.g. `leads@legacywestdevelopment.com`)?
- Or the specific team member selected in the form's "Submitted By" dropdown (Nicholas, George, Aaron, or Quinton)?

> If per-person, this requires each team member's own Gmail to be authorized individually (more setup), rather than one shared credential.

### 3. Close custom fields
- Do the custom fields already exist in Close (**Settings → Custom Fields**)?
- If yes: what are the exact field **IDs** (not just names) for: project type, fire-affected flag, insurance status, rep/submitted-by?
- If no: these need to be created in Close first, since custom field IDs are generated by Close and can't be predicted in advance.

### 4. Email template content
- Do written templates already exist for:
  - The **standard** follow-up email?
  - The **fire-recovery** follow-up email (for leads where `fireAffected === "yes"`)?
- If not, these need to be drafted (by you, or with my help) before the "draft-creation" logic can be built — the code needs real copy to insert lead details into.

### 5. Scope/rollout order
Given the amount of new setup involved (Google Cloud Console project, Gmail API scopes, Close custom field creation), should this be built:
- **All at once**, or
- **Incrementally** — e.g., first migrate Close integration to use real custom fields (lower risk, no new external service), then add Gmail draft creation as a separate follow-up phase once that's stable?

## Proposed Data Flow (Once Built)

```
┌─────────────┐      POST /api/create-lead       ┌──────────────────┐
│   Browser    │ ────────────────────────────────▶ │  Express API      │
│ (React/Vite) │                                    │  (server.js)       │
└─────────────┘                                    └─────────┬────────┘
                                                              │
                                   ┌──────────────────────────┼───────────────────────────┐
                                   ▼                          ▼                            ▼
                          ┌─────────────────┐        ┌─────────────────┐        ┌────────────────────┐
                          │ Close CRM        │        │ Gmail API        │        │ Close Activity/Note │
                          │ Create Lead      │        │ Create Draft      │        │ "Draft created"      │
                          │ (custom fields)  │        │ (template select) │        │ logged back to lead │
                          └─────────────────┘        └─────────────────┘        └────────────────────┘
```

The fire-affected flag determines which branch is taken for the Gmail template step; both branches still create the Close lead and log the confirmation note the same way.
